## Draft release notes

- Configure native SMS Assist through Textbelt SMS's Configure screen. Enable it explicitly, enter an independent authorized-sender list, and select an Assist pipeline or use Home Assistant's current preferred pipeline. Preferred is resolved on each turn. Notification recipients do not grant Assist access.
- Start a reply-capable thread with `textbelt_sms.start_conversation`. Replies run the selected text pipeline without user routing scripts. Context is isolated per sender and resolved pipeline; `/new` starts fresh without running Assist.
- Configure standard notification recipients and send alerts with `notify.send_message`, including optional titles. Recipient identities survive reordering, removal/re-addition and reload. Existing dynamic `textbelt_sms.send_sms` and quota/last-message sensor identities remain available.
- Shared preparation preserves supported newlines, converts reviewed markup and punctuation, and splits long messages into labeled parts. The finite approved repertoire has 124 characters; each part is at most 160 GSM septets including labels, with at most five prepared parts. Oversized automation alerts fail before sending; native speech may compact or shorten visibly. Unsupported native speech gets a safe explanatory response.
- Signed callbacks now verify timestamp/HMAC over the original body, correlate accepted outgoing IDs with their recipients, and apply independent native authorization. The generated per-entry callback identity persists through restart. The fixed legacy endpoint is signed and events only.
- Accepted part IDs, partial acceptance and uncertain submissions remain visible. Sending stops at the first failure without automatic retry; a response failure does not rerun Assist. Provider acceptance and whole-batch carrier delivery are separate outcomes. Quota refresh operates independently.

## Upgrade and configuration

1. Before any authorized deployment that risks HA files, verify a usable Home Assistant backup and record the installed version and configuration. Install the separately approved candidate/version and restart HA. No deployment was performed for this handoff.
2. Existing entries migrate with native Assist disabled, preserving the API key, recipient options and existing sensors. Confirm outbound alerts and entity identities before enabling native routing. Use your actual notification entity selected in HA's UI; do not assume the README example ID exists.
3. Disable old SMS-to-Assist automations/scripts, including `textbelt_sms_reply` listeners that invoke Assist or household actions, before enabling native Assist. Compatibility events still exist, so a second router can execute a second action. To retain custom routing alone, leave native Assist disabled: authenticated callbacks can remain events only.
4. In Configure, enter consenting authorized senders in explicit international `+` format, independently of notification recipients. Choose a valid pipeline or preferred and the inactivity timeout (default 1800 seconds). Number syntax does not establish country/account eligibility or actual deliverability.
5. Native mode needs a paid, reply-capable account and a public HTTPS HA external URL with `/api/webhook/<generated-webhook-ID>` reachable by Textbelt. This is the integration-generated persisted webhook ID, not the Home Assistant config entry ID. URL validation alone cannot prove reachability. Provider documentation recorded September 30, 2026 limits replies to US numbers; the public `textbelt` key and `_test` keys cannot enable/authenticate native replies. Do not substitute example hosts as live callbacks.
6. Use `textbelt_sms.start_conversation` with an authorized number, then reply to the received greeting. Canonical dynamic, notify and native sends use the generated endpoint. Supported legacy dynamic phone strings that cannot normalize as explicit international numbers use the signed fixed `/api/webhook/textbelt_sms_reply` callback, remain events only and skip native correlation metadata. Outstanding old fixed-endpoint replies never execute native Assist.

Security compatibility change: older unsigned callback consumers must not expect unsigned payloads to be accepted. The compatibility event interface survives authenticated admission; retaining an old router is an explicit events-only configuration choice, not a requirement for native use.

## Runtime, cost and privacy

Pipeline changes, inactivity expiry, reload, disable and restart clear volatile native context. Removing sender authorization revokes native access. Active and queued turns lost on shutdown are not replayed. After a timeout/error, check Home Assistant before resending because an action may already have completed. `/new` and greetings also send SMS and can cost credits.

The integration retains correlation metadata for seven days and suppresses identical admitted bodies for two minutes, plus exact signed-packet replay protection within its freshness policy. These are local policies, not verified provider reply/retry windows or an exactly-once promise. Exact trimmed `STOP`, `START` and `HELP` do not execute native Assist or cause an integration reply. Provider-managed STOP opt-out and recipient START opt-in remain separate; do not send unsolicited opt-out probes. HELP/callback interaction remains unresolved.

Five prepared parts constrain submissions, not billed credits. Provider sender/STOP additions and carrier segmentation can increase charges; check observed quota debit. Outgoing sensor attributes can expose message content to HA history/Recorder. Authenticated inbound events expose text to listeners, and conversation agents may store content under their own policies. The reply-state Store contains metadata, not transcripts; that is not a blanket promise that HA stores no SMS content.
