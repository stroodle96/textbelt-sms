## Current official provider documentation

Retrieved October 2, 2026 through the web reader. Short quotations are confined to the extracts below; all other statements paraphrase. No load-bearing difference was found against `provider-source-research.md` (September 30). This is a comparison of retrieved facts, not a provider operational guarantee.

**P1 — [Getting started](https://docs.textbelt.com/), sections Send/Response/Testing/Replies/Verifying/Custom data.** POST `/text` requires `phone`, `message`, `key`; `sender`, `replyWebhookUrl`, `webhookData` are optional. Examples use forms and JSON. Response fields are `success`, `quotaRemaining`, success-only `textId`, failure-only `error`; examples cover missing fields and exhausted quota, not a comprehensive HTTP/error taxonomy. `_test` suffix uses `/text` to validate a key: "credit will not be deducted from your account." It describes a would-send result; explicit non-delivery, content-validation coverage and special throttles remain unspecified. Replies require an outbound message with callback and US numbers; free `textbelt` key is excluded. JSON carries initiating `textId`, `fromNumber`, `text`, optionally `data`; custom data limit is 100 characters. Signature uses hex HMAC-SHA256/API key over timestamp concatenated with raw JSON, UTF-8 in Python example. Timestamp is UNIX seconds; documented maximum age is 15 minutes. Future-clock tolerance, reply lifetime, inbound ID and acknowledgment/retry rules are unspecified.

**P2 — [Sending and receiving](https://docs.textbelt.com/faq/sending-and-receiving-messages), phone/countries/rates/long texts/quota.** E.164 is preferred; US/Canada support ten digits/formatted strings. Form `+` requires encoding. Outbound coverage states 221 countries, without proving each account/carrier. Shared originating numbers are used; stability is attempted. Advice is 1–2 SMS/second rather than a strict API cutoff. Long-text wording includes "as of writing, 256 bytes" and usually 120 per carrier segment. Its byte definition/current hard request maximum are ambiguous; 306 ASCII accepted in the historical trial conflicts with treating 256 as an established universal limit. Separate SMS-capacity text states 140 bytes, 160 GSM characters or potentially 70 Unicode characters. These do not prove provider encoding, extensions, non-BMP, normalization or request limits. Quota counts carrier segments; failed delivery consumes quota, with no automatic refund. This is no exact per-part credit guarantee.

**P3 — [Other endpoints](https://docs.textbelt.com/other-api-endpoints), status/quota.** GET `/status/:textId` returns `status`: `DELIVERED`, `SENT`, `SENDING`, `FAILED`, `UNKNOWN`. Carrier receipts differ; delivered status does not establish exact received text. Status retention is up to one week, independent of any reply/correlation window. GET `/quota/:key` returns `success`, `quotaRemaining`; key-bearing URLs must not enter logs. Poll cadence and endpoint throttling are unspecified.

**P4 — [Compliance](https://docs.textbelt.com/compliance), sender/opt-out/opt-in.** Sender identification is required in each conversation. Initial messages may receive appended sender/STOP text; sender does not choose the originating number. Additions are outside the integration's prepared text and may affect credits. STOP is automatically handled; START must come from the recipient to opt back in. HELP behavior, command callback forwarding and rejection schema are unspecified.

**P5 — [Platform policies](https://docs.textbelt.com/faq/textbelt-platform-and-policies), allowed messages/quota/privacy.** Recipient consent is required; prohibited content includes spam, harassment and illegal messages. URLs need account whitelist permission. New-account phone/content logs may persist 60 days. Quota purchased after April 14, 2017 expires after 365 days without key usage. These facts establish no acceptance of arbitrary URL content or deterministic billing.

**P6 — [Troubleshooting](https://docs.textbelt.com/faq/troubleshooting), VOIP.** VOIP destinations are documented unsupported. No finite character allowlist or POST idempotency mechanism was found in the retrieved pages. Absence is not evidence those mechanisms cannot exist.

`/sms-replies` and `/llms.txt` remained inaccessible through the web reader. P1 itself contains the relevant reply/signature specification; their retrieval failure does not create new contract rules. No secondary telecom/carrier sources were added.
